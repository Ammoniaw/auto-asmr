# auto-asmr（Rust 版，带界面）

把任意人声变成"有人在你耳边说话"的双耳效果，戴耳机听。一个程序，两个功能：

- **实时**：麦克风 → 效果 → 耳机 / 虚拟声卡，给主播用。纯 CPU，算法延时 2.4 ms。
- **文件转换**：选一段音频，输出处理后的 WAV；也可以先"试听"，边听边调参数。

算法与仓库根目录的 Python 版 `asmr_binaural.py` 相同（Neumann KU100 人工头的实测近场 HRIR），界面用 Rust + egui，Windows / macOS / Linux 都能编译运行。

## 构建与运行

需要 Rust 工具链（<https://rustup.rs>）。

```bash
cd auto-asmr
```

```bash
cargo build --release
```

生成的程序在 `target/release/auto-asmr`（Windows 是 `auto-asmr.exe`）。HRIR、房间、耳机补偿数据都内嵌在程序里，单个文件即可运行，约 25 MB。

| 系统 | 说明 |
|---|---|
| Windows | 直接双击 `auto-asmr.exe`。直播时把输出设备选成虚拟声卡（如 VB-Cable）。 |
| macOS | 运行 `tools/bundle_macos.sh` 生成 `target/release/auto-asmr.app`，双击启动。打包后 macOS 才会弹出麦克风授权。 |
| Linux | 编译前需要 ALSA 开发库（Debian / Ubuntu：`sudo apt install libasound2-dev`）。 |

不带参数启动就是图形界面。界面文字默认中文，右上角可切换英文和明暗主题；关闭时会记住所有设置。

配置自动保存到**启动时的当前工作目录**中的 `auto-asmr.ron`，约每 30 秒保存一次，正常关闭时也会保存，下次启动从同一位置读取。双击 EXE 时通常就是 EXE 所在目录；从终端启动时则是终端的当前目录。该目录需要有写入权限。

右上角的**导出配置**可将当前效果参数、音频设备选择、缓冲、语言、页签和文件输出设置保存为 `.ron` 文件，无需等待自动保存。恢复时先关闭程序，将导出文件复制到运行目录并命名为 `auto-asmr.ron`，再启动程序。所选音频路径、截取起点和时长不保存；窗口和主题状态仅随自动保存记录。

## 实时模式

1. **音频设备**：程序自动查找本机设备，在下拉框里选输入（麦克风）和输出。插拔设备后点"重载设备列表"。
2. **缓冲**：越小延迟越低；出现爆音就调大。默认 256 帧。
3. 点**开始**。"输出效果 / 监听原声"可以随时切换，对比处理前后。
4. 右侧所有参数都可以边说话边调，立即生效。
5. 麦克风有底噪时，把窗口左下角的**降噪**滑条往右拖（0–100，0 = 关闭，见下面的参数表）。
6. 想自己决定声音在哪儿：勾上位置图下面的**手动摆位**。自动移动全部停掉（穿梭、忽远忽近、自动上下、自然晃动），声源停在你摆的位置——在位置图里点一下或拖动圆点改方位和距离，在图右侧的竖条上拖改高度（双击竖条回到与耳朵齐平）。声音会用零点几秒平滑地跟过去，不会跳，也没有咔嗒声；运行中勾上时，声源就停在此刻所在的位置。取消勾选后回到原来的自动模式，从当前位置接着走。

界面会显示算法延迟、估计的总延迟、每次回调的处理时间和断流次数；俯视图上能看到"说话人"此刻在你头边的位置。

延迟的构成（48 kHz）：

| 部分 | 时长 |
|---|---|
| 算法本身（分数延时插值 0.25 ms + 限制器前瞻约 2.1 ms） | 2.4 ms |
| 开启输入降噪时再加 | 20 ms |
| 输入缓冲 + 环形缓冲 + 输出缓冲（256 帧时） | 约 9 ms |
| 声卡驱动自身 | 取决于设备 |

处理量很小：每 128 个样本一块，平均 22 µs（Apple M 系列单核约 0.8%）；加上真实房间、降噪、去齿音、轻声化约 39 µs（约 1.5%）。

实时模式和文件模式有三点不同：

- **话少时也一直在动**。文件模式里动作严格跟着说话走：停顿时几乎不动，下一句从原位置接着说。直播时话少，或者麦克风底噪大、声音轻，说话检测认不出来，声音就会长时间停在一只耳朵边。所以实时模式里停顿超过 1 秒，动作就恢复正常速度；1 秒以内的短停顿仍然放慢。想让它完全不管说话、按固定节奏走，把"停顿时的动作"调到 1。
- 声音突然变大时，说话人是听到之后才往后让（文件模式能"预读"，会提前约 0.8 秒让开）。
- 响度靠"自动响度"慢慢拉到目标，而不是整段精确归一化。

## 文件转换

界面里选文件（或把文件拖进窗口），可以设置取哪个声道、从第几秒开始、处理多少秒、目标响度和位深。

- **试听**：用实时引擎直接播放，可以边听边调参数，满意后再转换。
- **转换并保存**：两遍处理，精确归一化到目标响度（默认 −16 LUFS），真峰值不超过上限。60 秒音频约 0.7 秒，10 分钟约 6 秒。

支持 wav / m4a / mp3 / flac / ogg 等常见格式（symphonia 解码）；输出 48 kHz 立体声 WAV。立体声输入只取一个声道，默认取更响的那个。

命令行也能用：

```bash
auto-asmr convert 输入.m4a -o 输出.wav --style ku100 --duration 60
```

```bash
auto-asmr --help
```

命令行里降噪是 `--denoise 12`（底噪最多压低 12 dB，范围 0–100）；只写 `--denoise` 是降到最干净。想单独听降噪的效果（不做空间化）：`auto-asmr decode 输入.m4a --denoise 12 -o 降噪后.wav`。

其他命令：`auto-asmr devices` 列出音频设备，`auto-asmr bench` 测处理速度，`auto-asmr rt-sim 音频文件` 不经过声卡、按实时模式把一个文件跑一遍并打印走位（可加 `--gain -30` 模拟小音量麦克风、`--noise -50` 加底噪、`--sparse 1.5/4` 模拟说 1.5 秒停 4 秒、`--manual "5:90,0.105,0;10:auto"` 模拟第 5 秒手动摆到右耳、第 10 秒切回自动）。

## 参数

| 分组 | 参数 | 作用 |
|---|---|---|
| 风格 | 贴耳加强 / KU100 实录 | 一键设置。贴耳加强：嘴离耳约 1.7 cm，另一只耳朵几乎听不到，不加房间。KU100 实录：按真实 KU100 录音标定，远耳听得到、离耳约 6 cm、真实房间、KU100 原机音色。 |
| 贴耳感 | 贴耳距离、远耳压低、临场感、暗度、温暖感、近耳低频、远耳低频削减 | 贴耳的程度和音色。 |
| 左右移动 | 模式（穿梭 / 随机走位 / 环绕 / 固定 / 手动）、移动频率、停留时间、移动时间、随机程度、从远处凑近、贴耳角度、从哪里绕 | 左右切换的方式和节奏。随机程度为 0 时完全规律。"手动"就是位置图下面的"手动摆位"：没有任何自动移动，位置由你拖动决定（也可以用这里的方位角、离头距离、高度三个滑条）；文件转换时相当于固定在这个位置。 |
| 忽远忽近 | 幅度、节奏、随机程度、跟随音量、退开时的音量、停顿时的动作、自然晃动 | 说话人在耳边凑近、往后让。跟随音量：声音大时往后让、轻声时更贴近。停顿时的动作 0.13 = 停顿里几乎不动，下一句从原位置接着说（实时模式下停顿超过 1 秒会恢复）。 |
| 上下 | 高度、自动上下、节奏、随机程度、从头顶绕 | 高度：嘴在耳朵上方（正）或下方（负）多少度，离耳朵的距离不变。自动上下：嘴在耳朵上方 / 下方之间慢慢换位置，0 = 关闭。从头顶绕：换耳时不从脸前 / 脑后绕，而是从头顶绕过去的概率。上下只靠耳廓对 5 kHz 以上高频的染色，比左右和远近弱，因人而异。 |
| KU100 临场感 | 真实房间、房间声大小、回放补偿 | 真实房间是 TH Köln 用同一个 KU100 实测的；回放补偿可选通用扩散场、KU100 原机音色，或 23 款耳机型号。 |
| 降噪（窗口左下角） | 一个 0–100 的滑条 | 输入降噪（RNNoise，纯 CPU），在空间化之前做，实时和文件转换都有效。数值 = 底噪最多压低多少分贝；0 = 关闭，100 = 不设上限，60 以上基本没有区别。风扇、空调这类稳定的底噪，设多少就降多少；嘶嘶的白噪声，降噪器自己最多只能压低二十多分贝。人声音量不变，气声的高频会被削掉一点（轻语实测：设 6 时约 1 dB，设 100 时约 2.6 dB），所以够用就行，不必拖到头。开启后延迟增加 20 ms。 |
| 人声处理 | 响应阈值、去齿音、轻声化 | 响应阈值以下的输入当作静音。都不改变嗓音本身。 |
| 输出 | 自动响度、目标响度、输出增益、峰值上限、随机种子 | 实时 / 试听时自动响度慢慢把音量拉到目标；限制器保证真峰值不超过上限。 |

每个参数在界面上悬停都有说明。各项的依据和文献见仓库根目录的 `README.md`。

## 和 Python 版的关系

同一套算法，逐项对照过：

- **固定轨迹下逐样本一致**：贴耳、6 cm + 房间、绕头 12 cm、绕头 20 cm + 房间、正前 0.5 m 五种情况，再加六种带高度的（贴耳向上 40°、6 cm 向下 30° + 房间、绕头时向上 35° / 60°、正前向上 45°、头顶正上方），Rust 与 Python 输出的相关系数都是 1.00000，残差 −63 到 −72 dB。
- **上下全关时与加入上下功能之前逐位相同**：高度 0、自动上下 0、从头顶绕 0 时，五种设置下输出文件逐字节一致。
- **随机走位的统计一致**（两边随机数不同，比的是整段 10.5 分钟的分布）：在侧边的时间 72% 对 72%，贴耳时离耳中位 3.0 cm 对 2.5 cm，换耳 66 次对 62 次，限制器最多压 5.5 dB 对 5.5 dB。

Rust 版多出来的：实时模式（含"话少时也一直在动"）、试听、输入降噪、噪声门、自动响度、随机走位模式、忽远忽近的随机程度。

Rust 版没有移植的：合成房间（treated / bedroom / living）、爆破音气团、`phrase` / `pingpong` / `wander` / `path` 运动模式。需要这些请用 Python 版。

## 开发

```bash
cargo test --release
```

26 个测试，包括：手动摆位时目标不动位置就纹丝不动、突然换位置时每 1.3 ms 最多挪 2 mm（不跳变）、自动与手动来回切换时位置连续、位置图的拖动换算与画图的刻度互为反函数、降噪各档在稳定底噪上降的分贝数与设定值相差不到 0.6 dB、降噪前后两路信号严格对齐、两级分块房间卷积与直接卷积逐样本一致、限制器不超过上限、BS.1770 响度读数、输入输出时钟相差 ±0.1% 时 60 秒不断流、话少时实时模式照常换耳、从头顶绕时位置连续、上下全关时仰角恒为 0。

| 路径 | 内容 |
|---|---|
| `src/dsp/` | 信号处理：数据表、直达声渲染、房间、运动、语音分析、人声处理、响度与限制器、引擎 |
| `src/realtime.rs` | 设备枚举、输入输出流、时钟漂移补偿 |
| `src/offline.rs` | 文件解码、两遍处理、写 WAV |
| `src/gui.rs` | 界面 |
| `assets/ku100.bin` | 内嵌数据（10.9 MB） |
| `tools/export_assets.py` | 从 Python 版的预处理结果重新导出 `assets/ku100.bin` |
| `tools/bundle_macos.sh` | 打包 macOS 应用 |

重新导出数据（一般不需要）：

```bash
uv run tools/export_assets.py
```

## 数据与许可

`assets/ku100.bin` 里的数据来自 TH Köln，均为 CC BY 4.0：

- 近场 HRIR 和耳机补偿滤波器：J. M. Arend、A. Neidhardt、C. Pörschmann，*Spherical Near-Field HRIR Compilation of the Neumann KU100*，[Zenodo 4297951](https://zenodo.org/records/4297951)。0.25 m 以内用刚性球头模型外推。高度修正取自同一数据集 1.5 m 的全球面测量（2702 个方向），做法和检验见仓库根目录的 `README.md`。
- 真实房间：T. Lübeck、J. M. Arend、C. Pörschmann (2021)，*A High-Resolution Spatial Room Impulse Response Database*，[Zenodo 5031335](https://zenodo.org/records/5031335)，去掉了直达声并缩短了混响时间。

输入降噪使用 [nnnoiseless](https://github.com/jneem/nnnoiseless)（RNNoise 的 Rust 移植）。
