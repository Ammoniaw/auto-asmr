# auto-asmr（Rust 版，带界面）

把任意人声变成"有人在你耳边说话"的双耳效果，戴耳机听。一个程序，两个功能：

- **实时**：麦克风 → 效果 → 耳机 / 虚拟声卡，给主播用。纯 CPU，算法延时 2.4 ms。
- **文件转换**：选一段音频，输出处理后的 WAV；也可以先"试听"，边听边调参数。

算法与仓库根目录的 Python 版 `asmr_binaural.py` 相同（Neumann KU100 人工头的实测近场 HRIR），界面用 Rust + egui，Windows / macOS / Linux 都能编译运行。

## 构建与运行

需要 Rust 工具链（<https://rustup.rs>）。

```bash
cd auto-asmr
```

```bash
cargo build --release
```

生成的程序在 `target/release/auto-asmr`（Windows 是 `auto-asmr.exe`）。HRIR、房间、耳机补偿数据都内嵌在程序里，单个文件即可运行，约 25 MB。

| 系统 | 说明 |
|---|---|
| Windows | 直接双击 `auto-asmr.exe`。直播时把输出设备选成虚拟声卡（如 VB-Cable）。 |
| macOS | 运行 `tools/bundle_macos.sh` 生成 `target/release/auto-asmr.app`，双击启动。打包后 macOS 才会弹出麦克风授权。 |
| Linux | 编译前需要 ALSA 开发库（Debian / Ubuntu：`sudo apt install libasound2-dev`）。 |

不带参数启动就是图形界面。界面文字默认中文，右上角可切换英文和明暗主题；关闭时会记住所有设置。

## 实时模式

1. **音频设备**：程序自动查找本机设备，在下拉框里选输入（麦克风）和输出。插拔设备后点"重载设备列表"。
2. **缓冲**：越小延迟越低；出现爆音就调大。默认 256 帧。
3. 点**开始**。"输出效果 / 监听原声"可以随时切换，对比处理前后。
4. 右侧所有参数都可以边说话边调，立即生效。

界面会显示算法延迟、估计的总延迟、每次回调的处理时间和断流次数；俯视图上能看到"说话人"此刻在你头边的位置。

延迟的构成（48 kHz）：

| 部分 | 时长 |
|---|---|
| 算法本身（分数延时插值 0.25 ms + 限制器前瞻约 2.1 ms） | 2.4 ms |
| 开启输入降噪时再加 | 20 ms |
| 输入缓冲 + 环形缓冲 + 输出缓冲（256 帧时） | 约 9 ms |
| 声卡驱动自身 | 取决于设备 |

处理量很小：每 128 个样本一块，平均 18 µs（Apple M 系列单核约 0.7%）；加上真实房间、降噪、去齿音、轻声化约 33 µs。

实时模式听不到"未来"，所以和文件模式有两点不同：声音突然变大时，说话人是听到之后才往后让（文件模式会提前约 0.8 秒让开）；响度靠"自动响度"慢慢拉到目标，而不是整段精确归一化。

## 文件转换

界面里选文件（或把文件拖进窗口），可以设置取哪个声道、从第几秒开始、处理多少秒、目标响度和位深。

- **试听**：用实时引擎直接播放，可以边听边调参数，满意后再转换。
- **转换并保存**：两遍处理，精确归一化到目标响度（默认 −16 LUFS），真峰值不超过上限。60 秒音频约 0.7 秒，10 分钟约 6 秒。

支持 wav / m4a / mp3 / flac / ogg 等常见格式（symphonia 解码）；输出 48 kHz 立体声 WAV。立体声输入只取一个声道，默认取更响的那个。

命令行也能用：

```bash
auto-asmr convert 输入.m4a -o 输出.wav --style ku100 --duration 60
```

```bash
auto-asmr --help
```

其他命令：`auto-asmr devices` 列出音频设备，`auto-asmr bench` 测处理速度。

## 参数

| 分组 | 参数 | 作用 |
|---|---|---|
| 风格 | 贴耳加强 / KU100 实录 | 一键设置。贴耳加强：嘴离耳约 1.7 cm，另一只耳朵几乎听不到，不加房间。KU100 实录：按真实 KU100 录音标定，远耳听得到、离耳约 6 cm、真实房间、KU100 原机音色。 |
| 贴耳感 | 贴耳距离、远耳压低、临场感、暗度、温暖感、近耳低频、远耳低频削减 | 贴耳的程度和音色。 |
| 左右移动 | 模式（穿梭 / 随机走位 / 环绕 / 固定）、移动频率、停留时间、移动时间、随机程度、从远处凑近、贴耳角度、从哪里绕 | 左右切换的方式和节奏。随机程度为 0 时完全规律。 |
| 忽远忽近 | 幅度、节奏、随机程度、跟随音量、退开时的音量、停顿时的动作、自然晃动 | 说话人在耳边凑近、往后让。跟随音量：声音大时往后让、轻声时更贴近。停顿时的动作 0.13 = 停顿里几乎不动，下一句从原位置接着说。 |
| KU100 临场感 | 真实房间、房间声大小、回放补偿 | 真实房间是 TH Köln 用同一个 KU100 实测的；回放补偿可选通用扩散场、KU100 原机音色，或 23 款耳机型号。 |
| 人声处理 | 输入降噪、响应阈值、去齿音、轻声化 | 降噪用 RNNoise（纯 CPU）。响应阈值以下的输入当作静音。都不改变嗓音本身。 |
| 输出 | 自动响度、目标响度、输出增益、峰值上限、随机种子 | 实时 / 试听时自动响度慢慢把音量拉到目标；限制器保证真峰值不超过上限。 |

每个参数在界面上悬停都有说明。各项的依据和文献见仓库根目录的 `README.md`。

## 和 Python 版的关系

同一套算法，逐项对照过：

- **固定轨迹下逐样本一致**：贴耳、6 cm + 房间、绕头 12 cm、绕头 20 cm + 房间、正前 0.5 m 五种情况，Rust 与 Python 输出的相关系数都是 1.00000，残差 −63 到 −72 dB。
- **随机走位的统计一致**（两边随机数不同，比的是整段 10.5 分钟的分布）：在侧边的时间 72% 对 72%，贴耳时离耳中位 3.0 cm 对 2.5 cm，换耳 66 次对 62 次，限制器最多压 5.5 dB 对 5.5 dB。

Rust 版多出来的：实时模式、试听、输入降噪、噪声门、自动响度、随机走位模式、忽远忽近的随机程度。

Rust 版没有移植的：合成房间（treated / bedroom / living）、爆破音气团、`phrase` / `pingpong` / `wander` / `path` 运动模式。需要这些请用 Python 版。

## 开发

```bash
cargo test --release
```

15 个测试，包括：两级分块房间卷积与直接卷积逐样本一致、限制器不超过上限、BS.1770 响度读数、输入输出时钟相差 ±0.1% 时 60 秒不断流。

| 路径 | 内容 |
|---|---|
| `src/dsp/` | 信号处理：数据表、直达声渲染、房间、运动、语音分析、人声处理、响度与限制器、引擎 |
| `src/realtime.rs` | 设备枚举、输入输出流、时钟漂移补偿 |
| `src/offline.rs` | 文件解码、两遍处理、写 WAV |
| `src/gui.rs` | 界面 |
| `assets/ku100.bin` | 内嵌数据（10.7 MB） |
| `tools/export_assets.py` | 从 Python 版的预处理结果重新导出 `assets/ku100.bin` |
| `tools/bundle_macos.sh` | 打包 macOS 应用 |

重新导出数据（一般不需要）：

```bash
uv run tools/export_assets.py
```

## 数据与许可

`assets/ku100.bin` 里的数据来自 TH Köln，均为 CC BY 4.0：

- 近场 HRIR 和耳机补偿滤波器：J. M. Arend、A. Neidhardt、C. Pörschmann，*Spherical Near-Field HRIR Compilation of the Neumann KU100*，[Zenodo 4297951](https://zenodo.org/records/4297951)。0.25 m 以内用刚性球头模型外推。
- 真实房间：T. Lübeck、J. M. Arend、C. Pörschmann (2021)，*A High-Resolution Spatial Room Impulse Response Database*，[Zenodo 5031335](https://zenodo.org/records/5031335)，去掉了直达声并缩短了混响时间。

输入降噪使用 [nnnoiseless](https://github.com/jneem/nnnoiseless)（RNNoise 的 Rust 移植）。
